TASK: Compress the day's entries into UP TO [[keep]] distilled memories. Output FEWER if the day lacks significant events. Never invent or inflate facts to reach the target number.

The calendar date in the header (=== YYYY-MM-DD ===) provides temporal context for understanding promises, deadlines, and chronology. Use it to ground scheduled actions, but do NOT include the date itself in your output.

1. CONCRETE: Specific actions, events, dates, entities, words, timestamps, locations, and sustained activities. Who did what, when, where, and why it matters.
2. EMOTIONAL: Raw feelings expressed or implied. Preserve intensity and tone.
3. RELATIONAL: How events affect relationships, trust, or group dynamics.
4. TECHNICAL: Facts about systems, architecture, capabilities, or constraints. Include ONLY if significant.
5. OTHER: Information that does not fit the above, BUT is demonstrably significant for understanding the day. USE SPARINGLY — this is a safeguard, not a catch-all.

STRUCTURE (flexible, not rigid):
- Begin with a time-of-day marker: "Morning:", "Afternoon:", "Evening:", "Night:", or "Late night:".
- Follow with the concrete fact — what happened, what was said, with essential context.
- If direct quotes or specific data exist, include them naturally.
- Add interpretation: what this reveals, why it matters.
- End with relational or systemic significance, if any.

RULES:
- Each memory = 2 to 4 sentences. Use 4 only when a direct quote, specific question, or deadline adds irreplaceable meaning.
- Target length per memory: 250-650 characters.
- Every memory string MUST start with a time-of-day marker followed by colon and space.
- If merging multiple related events, use the time of the most significant one.
- Remove duplicates and noise ruthlessly. If CONCRETE and EMOTIONAL conflict, prefer CONCRETE.

- Dates mentioned within events (promises, deadlines, scheduled actions) must be preserved.
- Do NOT include the calendar date in the memory text itself.

FORMAT: JSON array of 1 to [[keep]] strings. No other text, no preamble, no markdown fences.
